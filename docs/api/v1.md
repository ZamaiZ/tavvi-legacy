# Tavvi API v1

The Express service exposes one client-neutral API at `/api/v1`. Web and Mobile use the same paths, request schemas, response DTOs, and authorization policies. Next.js forwards server-side requests to these Express routes; it does not create a second product API.

Successful responses use `{ "data": ... }`. Failures use `{ "error": { "code": "...", "message": "..." } }`. The API package `@tavvi/api-contracts` owns shared schemas, DTO types, and route constants.

## Current routes

| Method | Path | Access |
| --- | --- | --- |
| POST | `/api/v1/auth/login` | Public, rate limited |
| POST | `/api/v1/auth/refresh` | Public, rate limited |
| GET | `/api/v1/auth/session` | Authenticated platform administrator |
| DELETE | `/api/v1/auth/session` | Authenticated session |
| POST | `/api/v1/auth/device-contract/login` | Public, rate limited |
| POST | `/api/v1/auth/device-contract` | Authenticated platform administrator |
| DELETE | `/api/v1/auth/device-contract` | Device proof, rate limited |
| GET | `/api/v1/platform/invitations` | Platform administrator |
| POST | `/api/v1/platform/invitations` | Platform administrator |
| GET | `/api/v1/platform/invitations/:id` | Platform administrator |
| POST | `/api/v1/platform/invitations/:id/rotate` | Platform administrator |
| POST | `/api/v1/platform/invitations/:id/revoke` | Platform administrator |
| GET | `/api/v1/platform/restaurants` | Platform administrator |
| GET | `/api/v1/platform/restaurants/:id` | Platform administrator |

Signup, restaurant workspace, menu, tags, media, appearance, and public-menu endpoints are introduced with their domain migration phases. The single `/api/v1` root is used; no mobile-specific compatibility route is retained.
